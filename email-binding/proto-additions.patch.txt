Deliberately NOT proposed (considered and rejected for v1.0):

  * No `enum ProtocolBinding`. `protocol_binding` is an open-form
    string by design (custom bindings use URIs, spec Section 5.8);
    an enum would break that extensibility for zero wire benefit.
  * No new messages for email/spreadsheet payloads. Both bindings
    carry the existing Task/Message/Part/Artifact objects in
    ProtoJSON; new types would fork Layer 1, which this change
    explicitly leaves unchanged.
  * No tenant-field semantics for either binding. EMAIL routes by
    mailbox; SPREADSHEET by (spreadsheet ID, tab). `tenant` stays
    unused by both, and the amendments say so by omission.
